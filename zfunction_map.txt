### **inputs.py**

3.  **Inputs.initialize_hardware_inputs**

    *   **Description**: Toggles "velocity map mode" (or "single note mode"). In this mode, all pads play a single MIDI note but with different velocities. It updates the display and NeoPixels.
    *   **References**: `inputs.py`: `Inputs.handle_fn_button_held_fast`

7.  **Inputs.process_nav_buttons**
    *   **Description**: Processes the state of the FN and encoder navigation buttons. It detects presses, holds, and double-presses, then triggers appropriate menu or global actions.
    *   **References**: `inputs.py`: `Inputs.process_inputs_slow`

8.  **Inputs._handle_fn_button_release**
    *   **Description**: Handles the release event of the FN button. It calls the appropriate action function, updates the FN button's display icon, and adjusts its NeoPixel color/blink state based on recording.
    *   **References**: `inputs.py`: `Inputs.process_nav_buttons`

9.  **Inputs._handle_fn_button_press**
    *   **Description**: Handles the initial press event of the FN button, including single and double presses. It triggers corresponding menu actions and updates the FN button's NeoPixel.
    *   **References**: `inputs.py`: `Inputs.process_nav_buttons`

10. **Inputs._handle_fn_button_held**
    *   **Description**: Processes the ongoing held state of the FN button. It updates the FN button's display icon and sets its NeoPixel color to indicate being held.
    *   **References**: `inputs.py`: `Inputs.process_nav_buttons`

11. **Inputs.handle_encoder_arp_mode**
    *   **Description**: Manages pad interactions when in 'encoder' (arpeggiator) or 'chord' play modes. It adds notes/chords to the arpeggiator when pads are pressed and the encoder is turned clockwise.
    *   **References**: `inputs.py`: `Inputs.process_inputs_fast`

12. **Inputs.process_inputs_slow**
    *   **Description**: Processes inputs that do not require high-frequency polling, such as encoder turns, button hold detection, and navigation menu actions. It's called at a slower rate to save processing power.
    *   **References**: `code.py`: `main loop`

13. **Inputs._process_button_holds**
    *   **Description**: A helper function that iterates through all pad buttons to check for and update their held states. It returns the count of currently held pads.
    *   **References**: `inputs.py`: `Inputs.process_inputs_slow`

14. **Inputs.process_inputs_fast**
    *   **Description**: Processes high-frequency inputs like pad presses and releases. It handles note triggering, arpeggiator events, and special actions when the FN button is held, optimizing for minimal latency.
    *   **References**: `code.py`: `main loop`

15. **Inputs.process_keymatrix**
    *   **Description**: Reads and processes events from the keypad matrix. It updates the state of individual `Button` objects and returns a list of pads that were just pressed.
    *   **References**: `inputs.py`: `Inputs.process_inputs_fast`

16. **Inputs.reset_pads_and_notes**
    *   **Description**: Resets the action flags for all pad buttons and clears the lists of new note-on and note-off events, preparing for the next processing cycle.
    *   **References**: `inputs.py`: `Inputs.process_inputs_fast`

17. **Inputs.handle_fn_button_held_fast**
    *   **Description**: Handles pad presses when the FN button is held down in 'fast' input mode. It triggers actions like toggling velocity mode or starting chord recording based on the current play mode.
    *   **References**: `inputs.py`: `Inputs.process_inputs_fast`

18. **Inputs.play_arp_events**
    *   **Description**: Retrieves the next note and CC events from the `arpeggiator` module. It adds them to the `new_notes_on` and `new_notes_off` queues for processing and sends CC events directly.
    *   **References**: `inputs.py`: `Inputs.process_inputs_fast`

19. **Inputs.get_note_and_velocity**
    *   **Description**: Determines the MIDI note and velocity to be played for a given pad. It accounts for "velocity map mode" and the standard note mapping.
    *   **References**: `inputs.py`: `Inputs.process_inputs_fast`

20. **Inputs.get_button_states_list**
    *   **Description**: Returns a list of booleans representing the current pressed/released state of all 16 pad buttons.
    *   **References**: `inputs.py`: `Inputs.process_inputs_slow`

    *   **References**: `inputs.py`: `Inputs.handle_fn_button_held_fast`

3.  **ChordManager._create_new_chord**
    *   **Description**: A helper function that creates a new `MidiLoop` instance for a specified pad, initializes it for recording, and updates associated display elements (notification, pixel blink/color).
    *   **References**: `chordmanager.py`: `ChordManager.add_remove_chord`

4.  **ChordManager._remove_chord**
    *   **Description**: A helper function that clears a chord from a specified pad. It resets associated pixels, clears the `MidiLoop` object, and stops recording.
    *   **References**: `chordmanager.py`: `ChordManager.add_remove_chord`

5.  **ChordManager.check_event_limits**
    *   **Description**: Checks if the active recording chord has exceeded its event limits (notes or CCs). If so, it automatically stops recording to prevent memory issues.
    *   **References**: `code.py`: `main loop`

6.  **ChordManager.handle_fn_press**
    *   **Description**: Handles the FN button press when a chord is being recorded. It stops the recording, prepares the chord for playback (queueing if MIDI sync is on), and updates pixel states.
    *   **References**: `playmenu.py`: `double_click_fn_button` (commented out), `menus.py`: `midibank_menu` (`fn_button_press_function`), `code.py`: `record_cc_messages`, `main loop`

7.  **ChordManager.change_loop_mode**
    *   **Description**: Toggles the playback mode of an existing chord loop between "oneshot" and "chordloop". It resets the loop, clears pixels, and updates related display notifications.
    *   **References**: `playmenu.py`: `pad_held_function`

8.  **ChordManager.display_chord_loop_mode**
    *   **Description**: Displays a notification showing the current loop type ("1 shot" or "Loop") for the chord on a specified pad.
    *   **References**: `playmenu.py`: `pad_held_function`, `chordmanager.py`: `ChordManager.change_loop_mode`

9.  **ChordManager.toggle_chord_playstate**
    *   **Description**: Processes a pad press to either add a chord to the playback queue (MIDI sync) or directly toggle its playback (non-MIDI sync). It handles special behavior for one-shot chords.
    *   **References**: `code.py`: `main loop`

10. **ChordManager.process_chord_on_queue**
    *   **Description**: Checks the playback queue and, if the MIDI clock is playing, initiates playback for any queued chords. This ensures synced chord starts.
    *   **References**: `code.py`: `process_chord_notes`

11. **ChordManager.stop_all_chords**
    *   **Description**: Stops all currently playing chords. This is typically called when a MIDI stop message is received.
    *   **References**: `code.py`: `main loop`

12. **ChordManager._stop_single_chord**
    *   **Description**: A helper function that stops a specific chord from playing. It clears its notes/pixels, resets its default color, and removes it from the playback queue.
    *   **References**: `chordmanager.py`: `ChordManager.stop_all_chords`, `handle_midi_sync_change`

13. **ChordManager._play_chord**
    *   **Description**: A helper function that toggles the playing state of a specific chord. It handles visual feedback (pixels) and resets the chord for playback.
    *   **References**: `chordmanager.py`: `ChordManager.toggle_chord_playstate`, `process_chord_on_queue`

14. **ChordManager.unique_notes**
    *   **Description**: Returns a list of unique MIDI note-on events (note, velocity, pad_idx, chord_idx) for the chord on a given pad.
    *   **References**: `inputs.py`: `Inputs.handle_encoder_arp_mode`

15. **ChordManager.unique_ccs**
    *   **Description**: Returns a list of unique MIDI CC events (CC number, value, pad_idx) for the chord on a given pad.
    *   **References**: `inputs.py`: `Inputs.handle_encoder_arp_mode`

16. **ChordManager.save_chords_txt**
    *   **Description**: Saves all recorded chord data (notes, CCs, metadata) from all pads into a single CSV-formatted text file. Each pad's data is clearly demarcated.
    *   **References**: `settings.py`: `Settings.save_chords_to_file`

17. **ChordManager.initialize**
    *   **Description**: Initializes the ChordManager at application startup. It checks if a `chord_file_to_load` is specified in settings and, if so, loads the chord data from that file.
    *   **References**: `code.py`: `main loop`

18. **ChordManager.update_pad_pixels**
    *   **Description**: Refreshes the NeoPixel colors for all pads to reflect their current chord state (e.g., empty, active chord, playing, queued for play).
    *   **References**: `playmenu.py`: `double_click_fn_button`, `code.py`: `main loop`, `inputs.py`: `Inputs.handle_velocity_mode`

19. **ChordManager.finalize_chord_load**
    *   **Description**: A helper function called during chord loading to process a recently loaded chord. It generates its one-shot CC and note lists and trims its loop length.
    *   **References**: `chordmanager.py`: `ChordManager.load_chords_txt`

20. **ChordManager.load_chords_txt**
    *   **Description**: Loads chord data from a specified CSV-formatted file. It parses notes, CCs, and metadata for each pad, reconstructing `MidiLoop` objects and updating pixels during loading.
    *   **References**: `settings.py`: `Settings.load_startup_preset`, `chordmanager.py`: `ChordManager.initialize`

21. **ChordManager.handle_midi_sync_change**
    *   **Description**: Manages the state of all chords when the global MIDI sync setting changes. If sync is disabled, it stops all playing chords and clears their queues.
    *   **References**: `code.py`: `process_chord_notes`
